Used for requests from the service auditor, the certification body and the internal auditor alike. One
format, one queue, one owner — because three parallel request processes is how a programme loses track of
what it has already provided and to whom.

| Field | Guidance |
|---|---|
| Request ID | `ER-nnn`, sequential across all requesting parties |
| Requesting party | Ashcombe &amp; Doyle · Northgate · Camberwell · Ironwood |
| Date received / date due | Due date agreed, not assumed |
| Control or criterion | What the request relates to |
| Request as received | Verbatim. Do not paraphrase a request before answering it |
| Interpretation | What CloudNimbus understood the request to mean, where it was not literal. Confirmed with the requester before work started, where material |
| Population and period | What the evidence covers |
| Response | What was provided, itemised |
| Artefacts | Evidence store references |
| Provided by / date | Named individual |
| Follow-up | Any supplementary request arising, with its own ER number |

**Record the interpretation.** A request answered against a different question than the one asked is the
most common cause of a second-round request, and the second round costs more than the first because it
arrives with the requester already unsatisfied.
